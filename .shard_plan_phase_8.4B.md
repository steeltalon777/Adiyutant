## 1. Design Decisions (locked)

| # | Decision | Value |
|---|---|---|
| D1 | Migration version | **v4** (after v3 bundle-import-history) |
| D2 | Migration name | `"v0.4-projects-roadmaps"` |
| D3 | Foreign key enforcement | Enable `PRAGMA foreign_keys = ON;` in `run_migration` and test it |
| D4 | Selector syntax | `project/roadmap/phase/item` separated by `/`. Unqualified slugs allowed only when unique |
| D5 | Take-item duplicate behavior | **Idempotent** — if `roadmap_item_id + daily_log_id` already linked, return existing link + plan_item. No new rows. No error. |
| D6 | Item dependency resolution | References to sibling-item slugs within the same roadmap must resolve. Unresolved → **error** (per TZ). |

| D10 | `replace` mode | NOT supported. Only `append` and `merge` per 8.4A. |
| D11 | Roadmap item `status` enum | `planned / active / blocked / done / skipped` |
| D12 | Project `status` enum | `active / paused / done / archived` |
| D13 | Roadmap `horizon` enum | `week / month / quarter / custom` |
| D14 | Phase `status` enum | `planned / active / done / skipped` |
| D15 | CLI `take-item` date args | `today` or `tomorrow` only. Service accepts `NaiveDate` internally. |

### 3.2 Domain models (Unit A creates)

**`model/project.rs`** — `Project` struct with:
- `id: Id<Project>`, `slug: String`, `title: String`, `description: Option<String>`, `status: ProjectStatus`, `priority: u8`, `why: Option<String>`, `created_at: AdiyutantDateTime`, `updated_at: AdiyutantDateTime`
- `ProjectStatus` enum: `Active | Paused | Done | Archived` with `as_str()` / `from_str()` round-trip
- `Project::new(slug, title)` constructor

**`model/roadmap.rs`** — `Roadmap`, `RoadmapPhase`, `RoadmapItem`, `RoadmapPlanLink`, and status/horizon enums:
- `Roadmap`: `id, slug, project_id, title, description, horizon: RoadmapHorizon, status: ProjectStatus, created_at, updated_at`
- `RoadmapPhase`: `id, slug, roadmap_id, title, order_index, status: PhaseStatus`
- `RoadmapItem`: `id, slug, phase_id, title, description, status: RoadmapItemStatus, priority, acceptance_criteria: Vec<String>, depends_on: Vec<String>, links: Vec<String>, created_at, updated_at`
- `RoadmapPlanLink`: `id, roadmap_item_id, plan_item_id, link_type: String ("taken_into_day"), created_at`
- `RoadmapHorizon`: `Week | Month | Quarter | Custom` with round-trip
- `PhaseStatus`: `Planned | Active | Done | Skipped` with round-trip
- `RoadmapItemStatus`: `Planned | Active | Blocked | Done | Skipped` with round-trip
- Constructors `::new(...)` for all

All enums use `#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]` with kebab-case `#[serde(rename_all = "kebab-case")]` for the bundle-side, and `as_str()` returning lowercase with hyphens for storage.

**Storage strings:**
- `ProjectStatus::Active.as_str() => "active"`
- `RoadmapHorizon::Week.as_str() => "week"`
- `PhaseStatus::Planned.as_str() => "planned"`
- `RoadmapItemStatus::Active.as_str() => "active"`
- `RoadmapItemStatus::Blocked.as_str() => "blocked"`

### 3.5 Take-item composite (parent adds to `store.rs`)

```rust
/// Composite input for `take_roadmap_item_composite`.
pub struct TakeRoadmapItemInput<'a> {
    pub roadmap_item_id: Id<RoadmapItem>,
    pub target_date: NaiveDate,
    pub daily_log_to_create: Option<DailyLog>, // None if log exists
    pub plan_item: PlanItem,
    pub initial_checkpoint: TaskCheckpoint,
    pub link: RoadmapPlanLink,
    /// If true and current item status is Planned, transition to Active.
    pub activate_item: bool,
}

pub struct TakeRoadmapItemResult {
    pub plan_item_id: Id<PlanItem>,
    pub link_id: Id<RoadmapPlanLink>,
    pub plan_item_reused: bool,
    pub link_reused: bool,
}

fn take_roadmap_item_composite(
    &self,
    input: TakeRoadmapItemInput<'_>,
) -> Result<TakeRoadmapItemResult, Self::Error>;
```

**Behavior:**
1. Check if a `RoadmapPlanLink` exists with `(roadmap_item_id, plan_item_id)` for an existing `plan_item` on the same `target_date` → if yes, return `TakeRoadmapItemResult { plan_item_reused: true, link_reused: true, ... }` and short-circuit. No writes.
2. Else: create daily_log if needed, insert plan_item, insert checkpoint, insert link, optionally update roadmap_item status. All in one transaction.
3. Returns the new IDs.

This requires `Transaction` support in the trait. Either:
- Add a new generic `transaction(...)` method to `Store` trait, **or**
- Add a bounded method specifically for take-item.

**Decision:** Add `take_roadmap_item_composite` as a specific Store method (matches existing pattern of `start_plan_item_composite` etc.). The implementation in `SqliteStore` will use the existing `with_transaction` helper.

### 3.6 Bundle section validation rules (Unit C implements)

When `apply_bundle_inner` processes `bundle.projects` and `bundle.roadmaps`:
- Use `mode` (Append or Merge) to decide create-vs-update-vs-skip
- For each `BundleProject`: lookup by slug; if exists and `Merge` → update; if exists and `Append` → skip_existing; else → create
- For each `BundleRoadmap`: lookup by `(project_slug, slug)`; resolve project first
- For each `BundleRoadmapPhase`: lookup by `(roadmap_slug, phase_slug)`; resolve roadmap first
- For each `BundleRoadmapItem`: lookup by `(phase_slug, item_slug)`; resolve phase first
- All-or-nothing transaction
- Validate `depends_on` references resolve to siblings in the same roadmap
- Validate slug uniqueness within a section
- Validation runs in `validate_bundle` (returns errors → preview/apply abort)

## 4. Migration v4 SQL (parent adds to `adiyutant_store/src/lib.rs`)

```sql
-- v0.4-projects-roadmaps
PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS projects (
    id TEXT PRIMARY KEY,
    slug TEXT NOT NULL UNIQUE,
    title TEXT NOT NULL,
    description TEXT,
    status TEXT NOT NULL DEFAULT 'active',
    priority INTEGER NOT NULL DEFAULT 5,
    why TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL

CREATE TABLE IF NOT EXISTS roadmaps (
    id TEXT PRIMARY KEY,
    slug TEXT NOT NULL,
    project_id TEXT NOT NULL REFERENCES projects(id),
    title TEXT NOT NULL,
    description TEXT,
    horizon TEXT NOT NULL DEFAULT 'month',
    status TEXT NOT NULL DEFAULT 'active',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,

CREATE TABLE IF NOT EXISTS roadmap_phases (
    id TEXT PRIMARY KEY,
    slug TEXT NOT NULL,
    roadmap_id TEXT NOT NULL REFERENCES roadmaps(id),
    title TEXT NOT NULL,
    order_index INTEGER NOT NULL DEFAULT 0,
    status TEXT NOT NULL DEFAULT 'planned',
    UNIQUE (roadmap_id, slug)

    id TEXT PRIMARY KEY,
    slug TEXT NOT NULL,
```

## 7. Critical contract invariants

- Store trait is the only persistence seam. No new SQLite calls outside the trait impls.
- All bundle apply writes must be inside `bundle_apply_composite` (or a clearly named sibling) — no service-level loops.
- `take_roadmap_item_composite` is atomic and idempotent (per D5).
- CLI never accesses `Store` directly; only via `AdiyutantCoreService`.
- Project/Roadmap DTOs do not contain `Id<T>` or `serde_json::Value`.
- No `#[allow(dead_code)]` for new public types. The new code must be reachable from the public API.
